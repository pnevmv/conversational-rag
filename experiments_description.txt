========================================================================
EVALUATION SET (v2 — balanced multi-domain)
========================================================================

All experiments use the same deterministic subset of 50 examples drawn
from the MultiDoc2Dial validation split. Examples are sampled via
round-robin interleaving across all four domains to ensure balanced
domain coverage:

  DMV: 13 examples, SSA: 13 examples, StudentAid: 12 examples, VA: 12 examples

Unanswerable examples (reference == abstention phrase): 3
These come from SSA, DMV, and StudentAid domains.

Using the same evaluation set across all experiments is intentional: it
allows the effect of each retrieval/knowledge mechanism to be studied
independently of any variation in test data.

Evaluation metrics:
  - Exact Match (EM): 1 if normalised prediction equals normalised
    reference, else 0. Normalisation: lowercase, remove punctuation,
    remove articles (a/an/the), collapse whitespace.
  - Token-level F1: harmonic mean of precision and recall computed over
    bag-of-words token overlap between normalised prediction and
    normalised reference answer.
  - Recall@K: fraction of gold grounding spans found in the top-K
    retrieved results. Each grounding entry is a (doc_id, id_sp) pair.
    With section-based indexing, a retrieved section counts as a hit if
    any of its constituent span IDs matches a gold grounding entry.
  - Domain Recall@K: fraction of top-K retrieved sections whose doc_id
    maps to the same domain as the gold grounding document. Measures
    whether the retriever stays in the right domain.
  - Abstain Rate: for unanswerable examples, fraction where the model
    replied exactly "Unfortunately, no relevant information is found."

Prompt style (agent voice): all experiments use a 1-2 sentence agent-
voice prompt with few-shot examples — no bullets, no bold, no preamble.
Abstention phrase: "Unfortunately, no relevant information is found."

========================================================================
NOTE ON INDEXING: SPAN-LEVEL vs SECTION-LEVEL
========================================================================

All RAG experiments use section-level indexing: each section groups a
heading span with all following content spans until the next heading,
joined as a single retrieval unit. The section's span_ids field lists
all constituent span IDs so Recall@K can still be checked against the
dataset's original per-span grounding annotations.

This change reduced the corpus from 35,659 individual spans to 4,114
sections and produced a 10–20× improvement in Recall@K across all
retrieval methods.

========================================================================
EXPERIMENT 1 — LLM-ONLY BASELINE
========================================================================

Setup
-----
The model receives only the user question with no external context,
no retrieved passages, and no document information.

Prompt template:
  "You are a government services agent. Answer the customer's question
   in 1-2 plain sentences. No bullet points, no bold text, no preamble.
   If you don't know, reply exactly:
   'Unfortunately, no relevant information is found.'

   Customer: {question}
   Agent:"

Model: gpt-5.4-nano-smirnov (Azure OpenAI)
Examples evaluated: 50 / 50 (47 answerable, 3 unanswerable)
Failures: 0

Results
-------
  Exact Match       :  0.00%
  Token F1          : 14.09%
  Token F1 (answ.)  : 14.85%
  Token F1 (unansw.):  2.15%
  Abstain rate      :  0%

Interpretation
--------------
The model never abstains on unanswerable examples: without a context to
point at, it hallucinates plausible answers. F1 is non-trivial because
some domain-specific vocabulary overlaps between questions and answers.
The agent-voice prompt keeps output short, which limits garbage text.

========================================================================
EXPERIMENT 2 — RAG BASELINE (BM25)
========================================================================

Setup
-----
A BM25 retriever (BM25Okapi, rank-bm25 library) built over 4,114
sections from 488 MultiDoc2Dial documents across all four domains.

Retrieval method : BM25Okapi (lexical, no embeddings)
Corpus size      : 4,114 sections from 488 documents
top_k            : 5
Model            : gpt-5.4-nano-smirnov (Azure OpenAI)
Examples evaluated: 50 / 50 (47 answerable, 3 unanswerable)
Failures          : 0

Results
-------
  Exact Match       :  4.00%
  Token F1          : 20.69%
  Token F1 (answ.)  : 17.75%
  Token F1 (unansw.): 66.67%
  Abstain rate      : 67%
  Recall@1          : 12.00%
  Recall@5          : 22.00%
  Domain Recall@5   : 58.00%

Interpretation
--------------
Best abstain rate (67%) of all experiments. BM25 sometimes retrieves no
relevant text for unanswerable questions, correctly triggering abstention.
Domain recall is lowest (58%): cross-domain lexical overlap (e.g. SSA
and VA both use "benefits/disability") causes wrong-domain hits.
Answerable F1 (17.75%) is lower than dense/hybrid.

========================================================================
EXPERIMENT 3 — RAG DENSE BASELINE (BGE-SMALL)
========================================================================

Setup
-----
Dense retriever using BAAI/bge-small-en-v1.5 (384-dim embeddings),
cosine similarity, disk-cached index. BGE asymmetric retrieval: queries
prepended with instruction prefix; section embeddings without prefix.

Retrieval method : Dense cosine similarity (bge-small-en-v1.5)
Embedding dim    : 384
Corpus size      : 4,114 sections from 488 documents
Index build time : ~15 seconds on Apple MPS (cached thereafter)
top_k            : 5
Model            : gpt-5.4-nano-smirnov (Azure OpenAI)
Examples evaluated: 50 / 50 (47 answerable, 3 unanswerable)
Failures          : 0

Results
-------
  Exact Match       :  2.00%
  Token F1          : 19.24%
  Token F1 (answ.)  : 18.34%
  Token F1 (unansw.): 33.33%
  Abstain rate      : 33%
  Recall@1          : 20.00%
  Recall@5          : 38.00%
  Domain Recall@5   : 66.80%

Interpretation
--------------
Dense embeddings improve domain targeting (+8.8 pp vs. BM25 domain recall)
and Recall@1 vs. BM25 (+8 pp). Abstain rate drops to 33%: the dense model
retrieves semantically similar-looking text even for unanswerable questions,
giving the LLM something to work with and reducing abstentions.

========================================================================
EXPERIMENT 4 — RAG HYBRID BASELINE (BM25 + BGE-SMALL, RRF)
========================================================================

Setup
-----
Hybrid retriever combining BM25 and dense via Reciprocal Rank Fusion
(RRF, k=60, pool_factor=3). Each ranker retrieves 15 candidates; the
merged list is truncated to top_k=5.

Retrieval method : RRF over BM25 + bge-small-en-v1.5
pool_factor      : 3  (each ranker retrieves 15 candidates)
RRF k constant   : 60
top_k            : 5
Model            : gpt-5.4-nano-smirnov (Azure OpenAI)
Examples evaluated: 50 / 50 (47 answerable, 3 unanswerable)
Failures          : 0

Results
-------
  Exact Match       :  2.00%
  Token F1          : 21.77%  (best non-rewrite F1)
  Token F1 (answ.)  : 20.97%  (best non-rewrite answerable F1)
  Token F1 (unansw.): 34.36%
  Abstain rate      : 33%
  Recall@1          : 12.00%
  Recall@5          : 36.00%
  Domain Recall@5   : 63.60%

Interpretation
--------------
Best overall F1 without query rewriting. RRF fuses BM25 and dense
rankings, combining lexical precision with semantic coverage. Domain
recall sits between BM25 and dense as expected.

========================================================================
EXPERIMENT 5 — RAG HYBRID + MULTI-TURN QUERY REWRITING
========================================================================

Setup
-----
Before retrieval, a query rewriter (LLM call) receives the full
preceding dialogue history (window=6 turns) and rewrites the current
user turn into a self-contained search query. The rewritten query is
passed to the hybrid retriever (Experiment 4). The LLM answer generation
uses the original user question (not the rewritten query).

History window : last 6 turns (3 exchanges)
Retrieval      : Hybrid (BM25 + bge-small, RRF, pool_factor=3, k=60)
top_k          : 5
Model          : gpt-5.4-nano-smirnov (Azure OpenAI, both rewriter and generator)
Examples evaluated: 50 / 50 (47 answerable, 3 unanswerable)
Failures          : 0

Example rewrites:
  "yes"                        → "Does the requirement to include a
                                  deposit with the application for
                                  paying Dial-in search account fees apply?"
  "What are the fees for that?" → "What are the fees for DMV call
                                  center exemptions in New York City?"
  "Where can I find more info?" → "Where can I find more information
                                  about New York DMV vehicle registration
                                  insurance requirements?"

Results
-------
  Exact Match       :  0.00%
  Token F1          : 20.40%
  Token F1 (answ.)  : 21.70%  (best answerable F1 overall)
  Token F1 (unansw.):  0.00%
  Abstain rate      :  0%
  Recall@1          : 28.00%
  Recall@5          : 44.00%
  Domain Recall@5   : 87.20%  (best domain recall by far)

Interpretation
--------------
Query rewriting dramatically improves domain recall (+23.6 pp vs. hybrid)
and answerable F1 (+21.70%). The rewritten query is so specific that the
retriever always finds something plausible — which prevents abstention on
unanswerable examples (abstain rate 0%). This is the main failure mode:
better retrieval hurts unanswerable handling.

========================================================================
KEY TAKEAWAYS
========================================================================

1. Domain recall surfaces a real retrieval failure: only 58% of retrieved
   sections come from the correct domain in the BM25 baseline. Query
   rewriting nearly fixes this (87.2% domain recall).

2. Abstain behaviour is anti-correlated with retrieval quality: better
   retrieval means the LLM gets more (possibly off-topic but plausible)
   context and abstains less. BM25 abstains 67%, rewrite abstains 0%.

3. Hybrid RRF is the best single method when unanswerable handling matters
   (33% abstain, best overall F1 at 21.77%).

4. Query rewriting is the single biggest lever for answerable questions:
   best answerable F1 (21.70%) and best domain recall (87.2%). At the
   cost of one extra LLM call per turn.

5. The agent-voice prompt (1-2 plain sentences, no bullets/bold) keeps
   output tight and reduces hallucination tokens, but abstention control
   requires a retrieval signal — the LLM alone never abstains.

Step 4 (RAG) is now complete. Next steps:

1. Knowledge Graph construction (Step 5). Transform MultiDoc2Dial
   documents into structured graphs for entity- and relation-based retrieval.

2. KG-based retrieval (Step 6). Query the KG as a structured context

3. Graph RAG (Step 7). Combine structured KG evidence with section retrieval.

4. Agentic approaches (Step 8). Dynamic routing between retrieval tools
   with explicit conversation state management.

Recall@K and Domain Recall@K will be tracked alongside EM/F1 in all
future experiments to separate retrieval quality from answer generation.
