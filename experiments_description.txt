Experiments Description
Conversational System for RAG — MultiDoc2Dial Evaluation
Danil Smirnov, M.Sc. Computer Engineering, University of Padua
Supervisor: Prof. Gianmaria Silvello

========================================================================
EVALUATION SET
========================================================================

All experiments use the same deterministic subset of 50 examples drawn
from the MultiDoc2Dial validation split. Examples are consecutive
user→agent turn pairs extracted across all four domains (DMV, SSA, VA,
StudentAid) in sorted domain order, capped at 50.

Using the same evaluation set across all experiments is intentional: it
allows the effect of each retrieval/knowledge mechanism to be studied
independently of any variation in test data.

Evaluation metrics:
  - Exact Match (EM): 1 if normalised prediction equals normalised
    reference, else 0. Normalisation: lowercase, remove punctuation,
    remove articles (a/an/the), collapse whitespace.
  - Token-level F1: harmonic mean of precision and recall computed over
    bag-of-words token overlap between normalised prediction and
    normalised reference answer.

========================================================================
EXPERIMENT 1 — LLM-ONLY BASELINE
========================================================================

Setup
-----
The model receives only the user question with no external context,
no retrieved passages, and no document information.

Prompt template:
  "Answer the following question as accurately as possible.

   Question:
   {question}"

Model: gpt-5.4-nano-smirnov (Azure OpenAI)
Examples evaluated: 50 / 50
Failures: 0

Results
-------
  Exact Match : 0.00%
  Token F1    : 7.53%

Interpretation
--------------
Zero exact matches are expected: the reference answers are short,
precise agent utterances ("You will need to get insurance or we will
suspend your registration and license"), while the model generates
multi-paragraph explanations. The token-level F1 of 7.53% captures
incidental lexical overlap only.

The key qualitative finding motivating retrieval: the model misinterprets
ambiguous, domain-specific questions. For example, given:

  Question:  "My insurance ended so what should i do"
  Reference: "You will need to get insurance or we will suspend your
              registration and license"

The LLM-only model responded with general health insurance advice
(Healthcare.gov, COBRA, Medicaid), having no way to know the question
concerns DMV vehicle registration. Without access to the source
documents, the model defaults to its parametric knowledge, which may
match a different, more common interpretation of the question.

This result establishes the control condition. Any improvement in
subsequent experiments is attributable to the retrieval or knowledge
mechanism added.

========================================================================
EXPERIMENT 2 — RAG BASELINE (BM25)
========================================================================

Setup
-----
A BM25 retriever (BM25Okapi, rank-bm25 library) is built over all
35,659 spans extracted from 488 MultiDoc2Dial documents across all
four domains. Each span is treated as an independent retrieval unit,
matching the granularity of the dataset's gold grounding annotations,
which point to specific span IDs rather than full documents.

For each question, the top-5 spans are retrieved and formatted as a
context block, which is prepended to the prompt:

  "You are a helpful assistant. Answer the question using only the
   context provided below. If the context does not contain enough
   information, say so briefly.

   Context:
   [1] <document title>
   <span text>
   ...

   Question:
   {question}"

Retrieval method : BM25Okapi (lexical, no embeddings)
Corpus size      : 35,659 spans from 488 documents
top_k            : 5
Model            : gpt-5.4-nano-smirnov (Azure OpenAI)
Examples evaluated: 49 / 50
Failures          : 1 (Azure content filter false positive on example
                    389cc90cb2e3c1ef291ea78b73ece9d4_14 — retrieved
                    spans about licence suspension triggered a
                    self-harm classifier at medium severity)

Results
-------
  Exact Match  : 0.00%
  Token F1     : 12.11%  (evaluated on 49 examples)

  Retrieval quality (averaged over all 50 examples):
    Recall@1   : 1.67%
    Recall@5   : 2.33%

Comparison to LLM-only baseline
---------------------------------
  Token F1 delta : +4.58 percentage points  (+60.8% relative)

Best single-example improvement observed:

  Question:   "Why would the DMV contact me about a search?"
  Reference:  "The DMV may contact you to ask you about a search to
               make sure you comply with the Dial-In Terms of Service."
  LLM-only:   "The DMV typically wouldn't contact you about a search
               unless your situation is connected to an investigation
               involving motor-vehicle records..."  (F1: 0.087)
  RAG answer: "DMV may contact you about a DIAL-IN search you
               performed."  (F1: 0.571)

  Retrieved span [1] (score 21.0):
    "Will DMV contact me about the searches I perform using my
     DIAL-IN Search Account?"
    — DIAL-IN search accounts#3

Interpretation
--------------
RAG with BM25 improves token F1 by a relative 60% over the LLM-only
baseline, confirming that even modest lexical retrieval adds value over
purely parametric knowledge. When BM25 retrieves the correct document
family, the LLM produces a substantially more grounded answer.

However, retrieval quality is the primary bottleneck. Recall@5 of 2.33%
means BM25 almost never finds the correct span. There are two systematic
causes:

1. Vocabulary mismatch. BM25 is purely lexical. Many questions are
   short conversational fragments ("Yes", "No", "I need to change my
   address", "What if my insurance had lapsed?") with almost no keyword
   overlap with the relevant document span. Without semantic
   understanding or query expansion, BM25 cannot bridge this gap.

2. Missing conversation history. Each question is processed in
   isolation, without the preceding dialogue turns. Follow-up questions
   that are intelligible only in context ("Do you know where the centers
   are located?", "What are the fees for that?") cannot be resolved by
   single-turn BM25 retrieval.

Despite poor retrieval, F1 still improves because even off-target spans
from the correct broad domain help orient the LLM and suppress
out-of-domain hallucination.

Exact Match remains 0% for the same reason as the LLM-only baseline:
the model generates explanatory prose rather than reproducing the
verbatim short reference answers.

========================================================================
EXPERIMENT 3 — RAG DENSE BASELINE (BGE-SMALL)
========================================================================

Setup
-----
A dense retriever is built using the BAAI/bge-small-en-v1.5 embedding
model (sentence-transformers, 384-dimensional embeddings). The same
35,659 spans from 488 documents are indexed. Each span is embedded
once and the index is cached to disk (data/cache/) for subsequent runs.

Retrieval is exact cosine similarity via a matrix-vector dot product
over L2-normalised embeddings. The BGE asymmetric retrieval convention
is applied: queries are prepended with the instruction prefix
"Represent this sentence for searching relevant passages: " while
passage embeddings are built without any prefix.

The prompt template and top_k=5 are identical to Experiment 2,
ensuring a fair comparison of the retrieval method only.

Retrieval method : Dense cosine similarity (bge-small-en-v1.5)
Embedding dim    : 384
Corpus size      : 35,659 spans from 488 documents
Index build time : ~27 seconds on Apple MPS (cached thereafter)
top_k            : 5
Model            : gpt-5.4-nano-smirnov (Azure OpenAI)
Examples evaluated: 50 / 50
Failures          : 0

Results
-------
  Exact Match  : 0.00%
  Token F1     : 15.91%

  Retrieval quality (averaged over all 50 examples):
    Recall@1   : 3.67%
    Recall@5   : 6.00%

Comparison to previous experiments
------------------------------------
  Experiment          EM      Token F1   Recall@1   Recall@5   n
  LLM-only          0.00%     7.53%        —          —        50
  RAG BM25          0.00%    12.11%       1.67%      2.33%     49
  RAG Dense (bge)   0.00%    15.91%       3.67%      6.00%     50

  Token F1 vs LLM-only  : +8.38 pp  (+111% relative)
  Token F1 vs RAG BM25  : +3.80 pp  (+31% relative)
  Recall@5 vs RAG BM25  : +3.67 pp  (nearly tripled)

Interpretation
--------------
Dense retrieval consistently outperforms BM25 on all metrics. The
improvement in Recall@5 (2.33% → 6.00%) confirms the expected benefit
of semantic matching over lexical matching: the model can bridge
vocabulary gaps between conversational questions and document spans
that share meaning but not exact terms.

The absence of Azure content-filter failures (0 vs 1 for BM25) is
likely incidental — a slightly different set of top-5 spans was
retrieved for the problematic example, avoiding the trigger.

Despite the improvement, Recall@5 of 6.00% remains low. The ceiling
is imposed by the same structural problem as BM25: questions are
processed in isolation without dialogue history. Single-turn dense
retrieval cannot resolve follow-up turns such as "Yes", "No",
"Where can I find more info?", or "What are the fees for that?" — these
have no retrievable signal independent of the prior conversation.

The F1 progression (7.53 → 12.11 → 15.91%) is monotonically
increasing and each step is meaningful, establishing that retrieval
quality and answer quality are correlated. The gap between 15.91% and
a system with perfect retrieval (Recall@5 = 100%) represents the
remaining opportunity for improvement via hybrid search, multi-turn
query rewriting, and Knowledge Graph-based retrieval.

========================================================================
EXPECTED PROGRESSION
========================================================================

The three completed experiments establish a clear baseline ladder.
Future experiments are expected to improve along two axes:

Answer quality (EM / Token F1):
  Hybrid retrieval (BM25 + dense, merged via reciprocal rank fusion)
  is the next immediate step. It should raise both Recall@K and F1
  by combining the complementary strengths of lexical and semantic
  matching.

  Multi-turn query rewriting (LLM rewrites the current turn into a
  self-contained query using dialogue history) directly addresses the
  dominant failure mode — decontextualised follow-up questions — and
  is expected to produce the largest single improvement in Recall@K.

  Knowledge Graph retrieval would provide structured, relational facts
  supporting precise, entity-grounded answers — particularly for
  multi-hop questions spanning multiple documents.

  Graph RAG would combine structured graph evidence with unstructured
  passage context.

  Agentic approaches would dynamically route between retrieval tools
  and manage conversation state.

Retrieval quality (Recall@K):
  Recall@K will be tracked alongside EM/F1 in all future experiments
  to separate retrieval quality effects from answer generation quality
  effects. The current ceiling (Recall@5 = 6.00%) is primarily a
  single-turn retrieval limit, not a model limit.
